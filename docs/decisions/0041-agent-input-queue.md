# ADR 0041：Agent FIFO 输入队列

状态：已接受

## 背景

此前 `Agent.run` 仅在 Agent 空闲时接受输入。调用方在一个 turn 运行期间提交的新消息会立即失败，`AgentInbox` 也只是在同一同步调用内入队后立刻出队，无法提供排队语义。交互式 Host 需要能够在当前回复生成期间接收后续用户消息，但会话日志仍要求单 writer 和严格事件顺序。

## 决策

`Agent.run` 接纳输入后返回一个与该输入绑定的 promise。Core 使用私有 FIFO inbox 串行领取输入，并在前一个 turn 的成功、失败或取消结算完成后才启动下一 turn。每个输入独立保留调用方提供的取消信号与执行元数据；单个 turn 失败不会阻断后续输入。

同一时刻仍只有一个活动 turn。排队输入的调用方取消信号会立即将其从 inbox 移除并拒绝对应 promise，不创建 turn 或会话事件；已被领取的输入继续按既有 run 取消路径结算。`cancel` 只取消活动 turn；`stop` 停止后续接纳、取消活动 turn，并以 `AgentClosedError` 拒绝尚未开始的所有输入。`whenIdle` 在 inbox drain 完成前保持等待。输入在被领取时才预留 turn ID 并写入会话事件。

## 后果

Host 可以安全地接受运行期间到达的新用户消息，同时保持单 writer、可重放事件顺序与每个已开始 turn 的恰好一次结算。调用方需要为每个 `run` promise 单独处理成功或失败；排队不等同于将消息注入正在运行的模型请求或工具执行。

## 放弃的方案

- 在活动 step 中插入用户消息：需要改变模型请求、工具执行和会话事件的边界，且会破坏当前一个 turn 对应一个稳定执行单元的语义。
- 让 Host 自行串行化全部输入：会使所有 Host 重复处理停止、失败隔离和空闲等待语义，且不能保护直接使用 `Agent` 的调用方。
- 继续保留仅作同步入队/出队的 `AgentInbox`：没有可观察行为，也不能满足运行期间接纳输入的需求。
