# ADR 0052：以稳定 messageId 实现 Host 提交幂等性

状态：已接受

## 背景

同一用户输入可能因浏览器、代理或调用方超时而被重新提交。若 Host 每次都生成新的 `MessageId`，Core 会将其当作不同输入，再次执行模型和有副作用工具。会话事件日志已经持久化 `user.message.id`，但此前 Host 未将它暴露为调用方可稳定提供的身份。

## 决策

Kernel 与 Core 保持由调用方提供 `MessageId`、会话内不可重复的既有契约。Web Host 的消息请求必须包含受限格式的 `messageId`；CLI 的单轮 `run` 与 `resume` 接受可选 `--message-id`，未提供时保持一次性随机身份。

Web Host 先检查同一实例内尚未落盘的提交，再从会话日志重建已接纳消息：相同 ID 和内容不创建 turn，并返回原有的 `accepted` 或持久终态；相同 ID 与不同内容返回冲突。内存 pending 记录只覆盖并发窗口，持久日志才是重启后的权威来源。

## 后果

重试不会重复触发工具副作用，且不需要向模型可见会话事件加入新的幂等事实。调用 Web API 的客户端需要保存并重用 `messageId`；CLI 使用者若需要跨进程重试幂等性，必须显式提供 `--message-id`。

## 放弃的方案

- 每次 Host 请求都生成随机 ID：无法识别重试。
- 仅用内存 Map 去重：进程重启后会丢失判断依据。
- 将幂等键置于独立全局数据库：会重复已有会话事实，并额外引入存储一致性边界。
