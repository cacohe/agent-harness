# ADR 0046：收敛 Kernel 工具领域

## 背景

工具协议与工具事实分别散落在 `facts.ts`、`model.ts` 和 `tools/`，通用运行时又拆成多个仅供内部调用的文件。调用方难以从目录结构判断工具领域的完整边界。

## 决策

Kernel 的全部工具概念放入 `src/tools/`，且只保留两个模块：

- `protocol.ts`：工具调用、模型可见定义、结果、会话工具事件、执行上下文、策略与 Sandbox 契约。
- `runtime.ts`：注册、组合路由、授权包装、Sandbox 路由及仅供该运行时共享的辅助逻辑。

`facts.ts`、`model.ts`、`agent.ts` 和 `session.ts` 通过类型引用工具协议，不再自行声明工具类型。根入口继续导出相同的公共领域词汇。

## 后果

工具领域可从单一目录完整发现，且没有为内部辅助逻辑设置额外模块边界。类型依赖从会话和模型事实指向工具协议；这些均为 TypeScript type-only 引用，不产生运行时循环依赖。

## 放弃的方案

保留 `facts.ts` 和 `model.ts` 中的工具事实，并只移动运行时文件。该方案避免部分类型导入调整，却仍要求理解多个目录和文件才能获得完整工具协议。
